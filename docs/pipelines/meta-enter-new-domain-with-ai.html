快速进入新领域：AI 出草案 → 实践 → 按实情改 pipeline

进陌生领域时，先用多轮对话从 AI 逼出一般 pipeline，自己动手走一遍，再按真实情况改成可贴身的章程

草稿元原则自己定义2026-10-08入门AI实践修订

易学错觉：看懂步骤 ≠ 会做。价值在山底上路与山顶总结；中间必须亲自练。 原则全文

山底 · 快速上手

  1. 1
    直接问 AI，多轮把疑问问透

    不怕问得浅；围绕「目标 / 常见步骤 / 坑 / 我该先做什么」连续追问，逼出一条可照做的一般 pipeline（山底地图），而不是只收集名词。

  2. 2
    自己实践

    按草案真做一轮或数轮；深度只来自动手。此步不可跳过——AI 章程再完整也不能替你爬到山顶。

  3. 3
    按自己的实际情况完善 pipeline

    记下哪一步用得上、哪一步多余、缺了哪一步；改写成自己的 YAML（边界、工具、节奏），再归档进本仓库。

山顶 · 深度体悟

待实践：多轮追问怎样才算「草案够用可动手」；实践几轮后再改 YAML 时，最常改掉的是哪一类步骤（工具/顺序/边界）。

实践踩坑

尚无踩坑记录。每练一轮，在 YAML 的 practice 里追加一行 date + note。

心法

开门（问出草案）→ 放入（亲自实践）→ 关门（按实情修订）

何时使用

接触摄影/咖啡/装修/职场新题等任何「还没有亲身章程」的新领域时。

边界

AI 给出的是一般草案（山底），不是你的最终版；完善前至少要有实践痕迹，否则仍停留在易学错觉。与 life-renovation-toc-as-pipeline「拿来目录再改」同构，只是入口从书换成多轮对话。
