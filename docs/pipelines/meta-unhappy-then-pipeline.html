meta-unhappy-then-pipeline

不开心遇新问题就总结新 pipeline

把「不开心 + 新问题」变成开凿新章程的触发器，而不是只抱怨

草稿元原则自己定义2026-10-09meta触发自己定义

易学错觉：看懂步骤 ≠ 会做。价值在山底上路与山顶总结；中间必须亲自练。 原则全文

山底 · 快速上手

  1. 1
    捕捉信号

    记下此刻不开心的状态，以及新出现的具体问题（谁、什么场景、卡在哪一步）。

  2. 2
    检索能否并入

    先在本库搜是否已有同类 pipeline；能并入就追加 practice / 改 steps，不要盲目新建。

  3. 3
    抽出山底步骤

    若无可并入，按 meta-write-pipeline 写新 YAML：intent、可跟做的 steps、when_to_use、boundaries；标明 origin（自己定义 / 拿来主义）。

  4. 4
    指向山顶

    提醒自己：这条章程服务于「我有信心能够处理好生活中的各种事情」；summit 未练勿编。

山顶 · 深度体悟

待实践填充——山顶体悟只在练过之后写，不在看懂步骤时编。

实践踩坑

尚无踩坑记录。每练一轮，在 YAML 的 practice 里追加一行 date + note。

心法

当前状态不开心遇到了新的问题，就一定有新的pipeline需要总结。

何时使用

当前状态不开心，又遇到了以前章程盖不住的新问题。

边界

情绪波动但没有新问题类型时，先用已有心态/沟通类 pipeline，不必强行开新山。
