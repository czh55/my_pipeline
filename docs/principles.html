底层原则

步骤与章程

先有步骤，再谈熟练。另请牢记：看懂 pipeline ≠ 会做；山底与山顶有价值，中间必须亲自练。

大象进冰箱

如何把大象放进冰箱？

1. 开门

2. 放入

3. 关门

笑话的外壳下面，是一条跨行业、跨场景的底层原则：

**解决问题、做事，都有步骤和章程。**

做饭有步骤，沟通有步骤，学习有步骤，拍摄有步骤；工作任务、汇报也有步骤。你尚未经历的事，同样需要这套原则——只是步骤要等经验来填。

核心警示：易学错觉

Pipeline 往往只有简单几步，说起来人人都懂，听完好像立刻就会了——这和**菜谱**是同一类陷阱：菜谱一直都在，大家做出来的味道却千差万别。

**你对一条 pipeline 的感受有多深，取决于你有多少次类似的真实动手实践。**

它最容易让人**眼高手低**：把「看懂步骤」误当成「已经会做」。

山底与山顶

Pipeline 最大的价值，落在两端：

| 位置 | 价值 |

|------|------|

| **山底** | 快速上手：不知道从哪开始时，有章程可跟 |

| **山顶** | 个人总结：实践够了之后，把感受压成可复用的几步 |

**它不能帮你抄近路从山底瞬移到山顶。** 中间那一段山路，必须亲自走、反复练。本仓库记录章程，是为了让山底少迷路、让山顶有沉淀——不是替代攀爬本身。

本仓库在做什么

不是收集别人的「最佳实践清单」，而是：

1. 经历一件事

2. 抽出可复用的步骤

3. 写成 pipeline，标明适用与边界

4. 下次同类事直接照章程走，再反馈修订

能力像滚雪球：章程越多、越贴合你自己的生活，雪球越大——但每一圈雪，都来自真实踩过的路。

领域

| domain | 覆盖 |

|--------|------|

| `meta` | 原则本身、如何写 pipeline |

| `life` | 做饭、出行、家务、开车、装修等日常 |

| `communicate` | 对话、关系、表达、夫妻/父母沟通 |

| `learn` | 学习、复习、吸收、整理知识 |

| `create` | 拍摄、写作、制作 |

| `work` | 任务、汇报、协作 |

状态阶梯

  • `seed`：主题已记下，骨架待实践填充（允许「拿来主义」先占位）
  • `draft`：刚从一次经历抽出，待再跑一轮
  • `validated`：自己用过多次，步骤靠谱
  • `snowball`：已能教人 / 跨场景复用，进入能力滚雪球

`seed` 不是学会了，只是**别忘了这座山还要去爬**。

单条章程的写法（山底 / 山顶 / 踩坑）

每条 pipeline 固定三块，模板见 `content/TEMPLATE.yaml`：

| 区块 | 写什么 |

|------|--------|

| **山底 · 快速上手** | `steps`：看完就能跟做的 1-2-3 |

| **山顶 · 深度体悟** | `summit`：练过才懂的手感与判断；未练就写「待实践」，不要编 |

| **实践踩坑** | `practice[]`：每次照做追加 `date` + `note` |

易学错觉最常发生在：只填了山底、却以为已经登顶。

经历 → 章程 → 复用 · 山底上路，山顶沉淀 · 中间必须亲自练
